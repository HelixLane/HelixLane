# HelixLane SSH/SFTP 工作台实现规格

状态：待用户审阅；尚未进入本规格的产品代码实现。

## 目标与已有基础

将现有 Rust + GPUI Kit 0.8.0 的 Islands 工作台预览推进为原生远程工作台。
用户优先要求接近 IDEA 的美观、完整交互与多主题，其后完成绝大部分既定工作台功能；首批协议仅 SSH 与 SFTP。
中英文、原生 CLI/URI 唤起及两个 PuTTY/WinSCP 兼容启动器属于首版范围。

当前 main（64d2fae7f033336ae8ff270564fa8810c524ecc7）已有固定区域、分隔条、示例文件树、只读源码页签及演示终端。
当前没有真实 SSH/SFTP、资源管理、Services、自由停靠、布局持久化或多主题。
本规格替代旧规格中的“固定布局、深色预览、无持久化”限制，保留现有框架与视觉基础。

## 方案选择

此前讨论已经收敛为：一套全局停靠系统，中央多页签与递归分屏；Services 集中管理工具；视图可在 Services、四边与中央迁移。
每个资源不再嵌套一套完整工作台，协议切换也不自动重排外围工具。
相比固定预览布局，该方案开发成本更高，但直接满足多视图和四机 SFTP；相比双层工作区，避免重复的停靠和导航体系。
本次沿用原生 Rust + GPUI Kit；不改成 Web/Tauri，不复制其他产品代码。

## 视觉与国际化

- 延续 IDEA Islands 的紧凑工具条、低饱和背景、蓝色强调、轻边框、约 8–10px 圆角及 4–6px 区域间隔。
- 首批 Dark、Light 两套完整主题及 Follow System；正文、选中、悬停、禁用、边框、焦点、终端 ANSI 色均来自语义 token。
- 主题和语言可即时切换并保存；初始语言根据系统选择中文或英文，其他语言回退英文。
- UI、菜单、tooltip、对话框、错误映射与 CLI 帮助都使用消息 key；资源名、文件名及远端输出不翻译。
- 字体优先系统 UI 字体，终端使用可配置等宽字体并支持中文回退；禁止依赖在线字体。
- 默认 1440×900，支持 960×640；窄窗口按用户显隐状态收起工具，保持主页面可操作，不自动删除视图。
- 图标使用已有 Kit 资源；键盘焦点可见，拖动操作提供菜单替代；远程终端快捷键与宿主命令明确区分。
- 视觉验收必须实际查看原生应用的中英文、亮暗主题与四分屏截图；编译通过不代替视觉验收。

## 资源、连接、会话和视图

- Resource：稳定 ID、名称、组、标签、备注及连接配置列表。首期实现主机资源。
- ConnectionProfile：地址、端口、用户名、凭据引用、代理/跳板配置和主机密钥策略。
- SSH 和 SFTP 可使用同一份配置，不要求用户建立两个资源；允许 SFTP-only 账户。
- Session：实际运行的 SSH 传输、PTY、exec 或 SFTP 会话。视图不是底层连接。
- ViewInstance：唯一 ID、工具类型、目标模式、资源/会话 ID、位置、状态；同一工具允许多个实例。
- 正常主机默认可复用 SSH 传输与多个通道；堡垒机受限时可配置独立传输，绝不绕过服务端通道限制。
- 单通道配置下，同一传输不并发开启额外 exec/SFTP；不能满足时提示限制，用户显式选择新连接或关闭占用通道。

## 一套工作台与 Services

- 中央是 TabGroup/Split 递归树，每个叶子有自己的页签栏；支持横纵分割、移动、关闭和活动页签恢复。
- 四边允许停靠、标签分组、区域再次分割；视图可移到中央或独立窗口。
- Services 提供“按资源”和“按类型”两种树；选择节点显示其工具内容，支持独立页签。
- 同一视图迁移时保持实例 ID、连接、滚动位置与任务；需要副本时显式新建实例。
- 已移出的实例在 Services 保留入口与位置标识，点击只聚焦既有实例。
- 关闭视图、隐藏区域、断开连接和取消任务是不同操作。关闭有任务的视图时明确提供继续后台/取消任务选择。
- 默认左侧资源、中央 SSH/SFTP、底部 Services/Transfers，右侧辅助工具按需打开。
- 持久化分割方向、比例、工具位置、资源引用和非敏感页面状态；恢复时不自动提交命令、重启任务或复用过期认证令牌。
- 首版包含完整布局功能；实施时先完成单窗口停靠与中央分屏，再完成独立窗口与跨窗口迁移。

## 跟随与固定、运行规则

- 每个工具实例独立选择 Follow 或 Fixed。按类型打开默认 Follow；从具体资源打开默认 Fixed。
- 跟随目标取自所属应用窗口中最近激活的资源内容视图；点击工具自身、Services 分类节点、通知等不改变资源上下文，避免自我跟随循环。其他窗口的焦点不影响本窗口目标；独立工具窗继承来源窗口的上下文，来源窗口关闭后暂停跟随并提示选择来源或固定，不擅自切换目标。
- 不支持当前资源时显示不可用状态，不默默操作前一资源；清除旧结果或明确标记历史结果。
- 标题始终显示工具、实际资源及模式；切为 Fixed 固定当前资源；显式“新视图打开”创建固定实例并保留原跟随面板。
- 四台机器同时 SFTP 是四个固定视图，可中央 2×2 分屏；跟随视图的切换不影响它们。
- 运行规则独立为 Background 与 While Visible。可见是正在显示的页签/面板且所属窗口未最小化，不要求拥有键盘焦点。
- While Visible 仅暂停采集/刷新，不终止连接或用户任务；再次可见时补一次刷新并显示数据时间。
- Background 对工具当前目标运行，不为所有曾跟随的资源无限采集；需持续观察的资源使用固定实例。
- 切换目标取消旧刷新并以 generation/target ID 拒绝迟到结果；在途命令与任务使用提交时快照，绝不随焦点改写目标。

## SSH 与终端

- 密码、私钥及 passphrase、SSH agent、交互式认证；主机密钥首次确认与变更阻断。
- SSH 采用 Rust 协议库，终端采用成熟 ANSI/VT 状态机，GPUI 负责渲染、输入、选择与剪贴板；不把终端输出当普通日志文本。
- 首选候选为 russh、russh-sftp 与 alacritty_terminal；实施前检查实际 API、许可证和 GPUI Kit 版本兼容，锁定经过验证的版本。
- 支持 PTY、窗口 resize、Unicode/中文、ANSI 色、alternate screen、滚动回看、搜索、复制粘贴、bracketed paste 与多终端实例。
- 网络操作不阻塞 UI；连接、认证、断线、重试与取消状态明确。重连是新会话，不承诺恢复普通 shell 内存状态。
- 首版完整目标含 SSH 跳板链、本地/远程/动态端口转发；在基本直连稳定后接入。
- 内置 tmux 示例工具提供检测、列举、新建、重命名、切换；切换操作必须明确目标终端实例，不能仅凭服务器推断。

## SFTP 与任务

- 本地/远程双栏、地址栏、返回/前进/上级、排序、隐藏文件、快捷路径、多选与多个独立视图。
- 创建目录、重命名、权限、删除确认、上传下载及递归传输；符号链接显示为链接，递归默认不跟随。
- 冲突提供覆盖/跳过/重命名；上传采用临时目标再提交，避免中断留下貌似完整的文件。
- 传输管理器独立于视图，持有源、目标、资源/配置快照、进度、并发限制、重试与取消。
- 恢复传输需重新验证源/目标状态；不能仅按远端长度盲目续传。重启后提供恢复选择，不自动重放任务。
- 首版支持外部编辑器：下载临时文件、打开、检测保存、比较远端是否变化、确认回传；不扩展为代码 IDE。
- 四机文件页面独立；跨主机复制先经本机中转，展示真实路径和磁盘占用，不宣称服务端直传。

## 存储与插件边界

- 本机资源与设置采用 SQLite，启动迁移需版本化；布局采用版本化序列化数据，损坏时备份并回退默认布局。
- 密码/私钥口令使用系统凭据库，数据库与布局只保存 SecretRef；临时堡垒机令牌默认仅驻内存。
- 暴露 ToolProvider/ToolInstance/ResourceCapabilities 边界，所有内置工具先使用同一宿主接口。
- 首版为完整插件目标提供 gpui-shell JavaScript 宿主接入与一个示例面板，需先验证同进程视图承载和能力限制；插件商店、在线分发与复杂依赖不作为首版验收条件。
- JS 插件访问资源通过宿主能力接口，不直接获得全部凭据；卸载订阅与异步任务必须有生命周期。

## 入口与堡垒机

- GUI、原生 CLI、URI 共用主程序入口；help/version 不初始化 GUI。
- helixlane open 支持 SSH/SFTP、已保存资源 ID、临时连接、新视图/激活已有视图/新窗口。
- helixlane:// 注册由安装器管理；参数通过标准 URL 解析与编码，不使用 shell 拼接。
- 已运行时通过有本机用户访问限制的 IPC 转交请求；首版正常模式单实例，多窗口属于该实例。
- 两个独立薄启动器解析 PuTTY、WinSCP 的常见交互唤起参数并转为同一 OpenRequest。
- PuTTY 初版含 host、user@host、-ssh、-P、-l、-pw；密钥/-load 等需显式支持后列入兼容表，不能静默忽略。
- WinSCP 初版含 SFTP URL、远程初始路径、/sessionname、/newinstance；完整 /script、/command 自动化不冒充已兼容。
- URI 不含明文密码；为老堡垒机支持 CLI 密码入参，但不二次写入进程参数、日志或持久化；不承诺能消除原始调用方参数曝光。
- 外部连接默认临时，不自动加入资源库；未知关键参数、异常地址和不支持的协议明确报错。
- Windows 优先验证兼容启动器和 URI；macOS 验证 app bundle、终端入口与 URI；Linux 提供 desktop handler。

## 交付顺序与完成定义

1. UI：语义主题/中英文/资源与会话模型/Services/中央分屏及四边停靠/布局保存，使用显式标记的演示数据验证。
2. 基本协议：真实 SSH 终端、SFTP、凭据与主机密钥、资源 CRUD、传输任务。完成四机 SFTP 与终端并存。
3. 完整工作台：跟随/固定、可见/后台运行、独立窗口、跳板/转发、外部编辑、tmux、异常恢复。
4. 集成：统一 CLI/IPC/URI、PuTTY/WinSCP 启动器、gpui-shell 示例、打包文档与跨平台验证。

每阶段必须报告可运行内容、验证证据与未完成项；不可把演示页面称为真实连接。
最终验收包括：主题/语言切换不丢状态；移动视图不重复创建连接；四机 SFTP 无目标串线；隐藏面板不终止传输；跟随快速切换不写错资源；启动参数经三种入口得到一致连接请求。
基础检查为 fmt、check、Clippy、核心模型与解析器单元测试；SSH/SFTP 使用本机容器化 OpenSSH 测试密码/密钥/交互认证、SFTP-only、断线/冲突/取消与通道限制。平台密钥库和真实堡垒机另行实测。
GitHub CI 覆盖 Linux/macOS/Windows 构建与测试，图形交互和安装器注册需实际平台验收；未经观察不得标记通过。
